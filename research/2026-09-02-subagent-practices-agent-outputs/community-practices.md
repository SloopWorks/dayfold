# Community best practices for Claude Code subagents (mid-2026)

Scope: community collections, Anthropic engineering/blog posts, and GitHub issues, Dec 2024 – Aug 2026. Official docs are cited only where needed to settle a factual conflict. Labels: `[fact:url]` = stated in the source; `[opinion:source]` = the source's judgment or my synthesis.

## 1. Widely-cited collections and what they actually teach

**wshobson/agents** (94 plugins, 202 agents, 183 skills, 16 orchestrators) [fact:https://github.com/wshobson/agents]
- Organizes by *plugin* (agents + commands + skills together), not by a flat agents folder — the unit of reuse is a domain bundle.
- Explicit five-tier model table: Fable 5 for "longest-horizon autonomous work" (opt-in, premium), Opus for "architecture, security, code review, production-critical", Sonnet for "docs, testing, debugging", Haiku for "fast operational tasks".
- Skills are installable independently of agents ("skills only" path) — a hint that the knowledge layer outlives the worker layer.
- No stated guidance on when *not* to use subagents [fact:same].

**VoltAgent/awesome-claude-code-subagents** (110+) [fact:https://github.com/VoltAgent/awesome-claude-code-subagents]
- Fixed template: `name / description / tools / model` frontmatter, then "You are a [role]..." plus checklists and a "Communication Protocol" section.
- "Each agent has minimal necessary permissions": reviewers get `Read, Grep, Glob`; writers add `Write, Edit, Bash`; researchers add `WebFetch, WebSearch`.
- Same three-tier model routing (opus deep reasoning / sonnet everyday / haiku quick tasks); project-level agents override user-level on name conflict.

**anthropics/claude-code repo (Anthropic's own agents)**
- `pr-review-toolkit/agents/code-reviewer.md`: description opens "Use this agent when you need to review code... This agent should be used proactively after writing or modifying code", then three `<example>` blocks (Context / user / assistant / `<commentary>`), and — notably — tells the *caller* what input the agent needs ("the agent needs to know which files to focus on... specify this as the agent input") [fact:https://github.com/anthropics/claude-code/blob/main/plugins/pr-review-toolkit/agents/code-reviewer.md]. `model: opus`; issues scored 0–100; **only report ≥80**; every finding has file path + line; grouped Critical (90–100) / Important (80–89).
- `plugins/code-review`: dispatches 4 parallel agents (2× CLAUDE.md compliance for redundancy, 1× bug detector, 1× git-history), then one confidence scorer *per issue*, filtering <80 to drop "pedantic nitpicks" and "issues linters will catch" [fact:https://github.com/anthropics/claude-code/blob/main/plugins/code-review/README.md].
- `plugin-dev` templates: `tools: ["Read","Grep","Glob"]` for analysis agents, `model: inherit`, and output templates keyed by `src/file.ts:42` [fact:https://github.com/anthropics/claude-code/blob/main/plugins/plugin-dev/skills/agent-development/examples/complete-agent-examples.md]. `feature-dev` ships exactly three: `code-explorer`, `code-architect`, `code-reviewer` [fact:https://github.com/anthropics/claude-code/tree/main/plugins/feature-dev/agents].

**hesreallyhim/awesome-claude-code** (53k stars) [fact:https://github.com/hesreallyhim/awesome-claude-code]
- Agents are not a top-level category; "Agent Orchestration" is, listing workflow frameworks (AB Method, Claude Code Harness "Plan → Work → Review", RIPER, Ralph). The curation signal is process, not personas.
- Editorial bar rewards verification and honesty ("schemas force 'gap' status on unsupported claims").
- Points to Piebald's dump of built-in prompts; the built-in Explore prompt is strictly read-only and ends "Communicate your final report directly as a regular message - do NOT attempt to create files" [fact:https://github.com/Piebald-AI/claude-code-system-prompts/blob/main/system-prompts/agent-prompt-explore.md].

**Anthropic engineering posts**
- *Building effective agents* (Dec 2024): add complexity "only when it demonstrably improves outcomes"; five patterns incl. orchestrator-workers and evaluator-optimizer [fact:https://www.anthropic.com/research/building-effective-agents].
- *Multi-agent research system* (Jun 2025): every delegation needs "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries"; effort scaling ("1 agent with 3-10 tool calls... 2-4 subagents with 10-15 calls each"); "multi-agent systems use about 15× more tokens than chats"; and "most coding tasks involve fewer truly parallelizable tasks than research" [fact:https://www.anthropic.com/engineering/multi-agent-research-system].
- *Effective context engineering* (Sep 2025): subagents should return "a condensed, distilled summary of its work (often 1,000-2,000 tokens)" [fact:https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents].
- *When to use multi-agent systems* (Jan 23, 2026): three triggers (context protection, parallelization, specialization); "3-10x more tokens"; the "telephone game" at handoffs; "Group work by what context it requires, not by what kind of work it is"; "Start with the simplest approach that works" [fact:https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them].
- *Subagents in Claude Code* (Apr 7, 2026): signal = "ten or more files, or... three or more independent pieces of work"; don't use for sequential dependent work, same-file edits, small tasks, or with "too many specialist agents"; "Subagents... can't talk to one another" [fact:https://claude.com/blog/subagents-in-claude-code].

**Boris Cherny**
- Runs two custom agents: `code-simplifier` (after Claude finishes) and `verify-app` (end-to-end test instructions); treats subagents "as automations for the most common PR workflows" [fact:https://x.com/bcherny/status/2007179850139000872] [fact:https://github.com/shanraisshan/claude-code-best-practice/blob/main/tips/claude-boris-13-tips-03-jan-26.md].
- "Append 'use subagents' to any request where you want Claude to throw more compute at the problem" [fact:https://howborisusesclaudecode.com/].
- Jun 29, 2026: "subagents run in the background by default" [fact:https://x.com/bcherny/status/2071647677591466098].

## 2. Failure modes people report

- **Over-decomposition / description collisions.** Author who built 100 agents kept 12: 100+ agents create "description collisions — Claude's router either picks the wrong agent or none"; 2,000-word personas are a "persona tax" [opinion:https://dev.to/suraj_khaitan_f893c243958/i-built-100-claude-code-subagents-these-are-the-12-that-actually-earn-their-context-10nn]. Anthropic: too many specialists "reduce delegation reliability" [fact:https://claude.com/blog/subagents-in-claude-code]; Claude Code warns when combined descriptions exceed 15,000 tokens [fact:https://code.claude.com/docs/en/sub-agents].
- **Vague descriptions never fire.** "Reviews code for security issues before commits" routes better than "security expert" [opinion:https://www.tembo.io/blog/claude-code-subagents]. Auto-delegation regressions are also a recurring bug class: #47598 (Apr 2026, 8 agents + CLAUDE.md routing table, "never delegates") closed not-planned [fact:https://github.com/anthropics/claude-code/issues/47598]; see also #12794 [fact:https://github.com/anthropics/claude-code/issues/12794]. Lesson: don't rely on auto-delegation for anything that must happen — use hooks, `/skill` invocation, or explicit "use the X agent".
- **Duplicating CLAUDE.md in agent bodies.** Behavior changed during 2026: issues #34572 (Mar) and #62944 (May) showed subagents *not* receiving CLAUDE.md and confabulating that they had ("confidently answers yes and even paraphrases plausible-sounding content") [fact:https://github.com/anthropics/claude-code/issues/34572] [fact:https://github.com/anthropics/claude-code/issues/62944]. Current docs: non-fork custom subagents receive "every level of the CLAUDE.md hierarchy... including ~/.claude/CLAUDE.md, project rules, CLAUDE.local.md, and managed policy files"; only built-in Explore/Plan skip it [fact:https://code.claude.com/docs/en/sub-agents]. So restating CLAUDE.md in an agent body double-loads it today; reference rules by name instead, and verify with a canary rule on upgrade [opinion:mine].
- **Losing conversation context.** "Sub-agents start with zero context... They only receive the query Claude writes for them"; fixes: state the *objective* not just the task, preload via `skills:`, resume rather than respawn [fact:https://wmedia.es/en/tips/claude-code-subagent-context-loss]. Safety variant: #41356 — a "never retry connections to server X (fail2ban)" memory rule was bypassed by a fresh-context subagent, locking the user out of prod twice; closed not-planned [fact:https://github.com/anthropics/claude-code/issues/41356].
- **Returning too much.** #23463: 7 parallel auditors returned 15–37K chars each (~150K total) and the parent entered a permanent "Prompt is too long" loop; closed not-planned [fact:https://github.com/anthropics/claude-code/issues/23463]. Fix: write full output to a file, return a pointer + summary [opinion:https://software.rajivprab.com/2026/07/13/using-subagents-to-improve-claude-code/].
- **Concurrent edits.** "Two subagents editing the same file in parallel is a recipe for conflict" [fact:https://claude.com/blog/subagents-in-claude-code]; `isolation: worktree` exists but "Reserve it for agents that genuinely mutate files in parallel" [fact:https://hidekazu-konishi.com/entry/claude_code_subagents_and_orchestration_guide.html].
- **Cost.** 15× (Anthropic 2025), 3–10× (Anthropic 2026); community: "4-7x more tokens", agent teams "roughly 15x", and five parallel subagents on Pro hit rate limits "in under twenty minutes" [opinion:https://www.ksred.com/claude-code-agents-and-subagents-what-they-actually-unlock/]; "Defaulting every agent to Opus is like chartering a helicopter for every pizza delivery" [opinion:https://www.cloudzero.com/blog/claude-code-agents/].
- **Runaway subagents.** #61405: a one-claim verification became a 12-hour session; "no user-configurable timeout" [fact:https://github.com/anthropics/claude-code/issues/61405]. Mitigation: `maxTurns` [opinion:mine].
- **Silent tool denial.** Background subagents auto-deny unapproved tools "but the subagent keeps going" and may report "success-shaped output describing a change that does not exist on disk"; plugin subagents "drop hooks, mcpServers, and permissionMode"; `cd` doesn't persist between Bash calls [fact:https://www.tembo.io/blog/claude-code-subagents]. (Tembo's "subagents cannot spawn other subagents" is now outdated — docs allow three layers [fact:https://code.claude.com/docs/en/sub-agents].)
- **Reviewer over-reporting.** "A reviewer prompted to find gaps will usually report some, even when the work is sound" — tell it to flag only correctness/requirement gaps [fact:https://code.claude.com/docs/en/best-practices].

## 3. Canonical set for a solo dev on a KMP/Compose + Node API + ADR-heavy monorepo

Convergent community lists: dev.to 12 → core four `code-reviewer` (sonnet, RO), `test-runner` (haiku, "returns '3 tests failed, here's why' instead of 4,000 lines"), `debugger` (inherit), `security-auditor` (opus) [opinion:dev.to]; Tembo's five add `test-writer` and `doc-maintainer` (haiku) [opinion:tembo]; ksred's minimal three are all read-heavy summarizers [opinion:ksred]; Anthropic's feature-dev trio is explorer/architect/reviewer [fact:anthropics/claude-code]; rajivprab runs a 13-step pipeline (deep-explore → test-author → implementer → code-reviewer → verifier → agent-docs-maintainer) with every agent writing to `*-<task>.md` files [opinion:rajivprab].

My synthesis for this repo [opinion:mine, grounded above]:

| Keep as agent | Why | Model / tools |
|---|---|---|
| built-in `Explore` | Don't rewrite it | — |
| `code-reviewer` | Fresh-context diff review, ≥80 confidence, file:line | sonnet or opus; `Read, Grep, Glob` |
| `test-runner` | Gradle/KMP output is exactly the "4,000 lines" case | haiku; `Bash, Read, Grep` |
| `debugger` | Root-cause on stack traces, may edit | inherit; full tools |
| `security-reviewer` | Auth/device-grant/child-data guardrails; opus "pulls away" on subtle patterns [opinion:tembo] | opus; RO |
| `verify-app` | Boris's pattern; drives the agent-dev-loop snapshot/action log | sonnet; `Bash, Read` |
| `docs-maintainer` | CHANGELOG/backlog/docs sync after a change | haiku; write-enabled |

Better as skills / commands / sessions:
- **Planner/architect** → plan mode + built-in Plan agent; a planning *skill* carries the repo's ADR/design-first rules [opinion:mine].
- **ADR writer** → a skill (template + governance knowledge) invoked manually; ADRs are operator-gated here, so `disable-model-invocation: true` fits Anthropic's own guidance for side-effecting workflows [fact:https://code.claude.com/docs/en/best-practices].
- **Release/deploy verifier** → slash-command/skill with `disable-model-invocation: true`, plus a Stop hook or `/goal`; "Most slash commands map cleanly to skills, not subagents" [opinion:https://theaiarchitects.com/blog/claude-code-subagents-vs-skills].
- **PR babysitter** → a background session (`claude --bg`, Agent View) or a Routine, not a subagent; Anthropic itself names "PR babysitters" as long-running background sessions [fact:https://claude.com/blog/agent-view-in-claude-code].
- **Research/explore** → built-in Explore, or a `context: fork` skill when the *instructions* are the asset.

## 4. User-level vs project-level, and syncing

- Placement: project (`.claude/agents/`) = codebase-specific, committed; user (`~/.claude/agents/`) = personal toolkit; project wins on name conflict [fact:https://hidekazu-konishi.com/entry/claude_code_subagents_and_orchestration_guide.html] [fact:https://github.com/VoltAgent/awesome-claude-code-subagents].
- Contrarian: avoid global installs because they "pollute the context window"; keep a central repo and symlink *per project* so "A JavaScript project should only see JavaScript tools" [opinion:https://sionwilliams.com/posts/2026-03-13-dotfiles-agentic-workflows/].
- Sync options: (a) chezmoi with SessionStart `chezmoi update`, PostToolUse `chezmoi add` on `.claude` edits, Stop `chezmoi re-add`, `autoCommit/autoPush`; excludes `credentials.json`, `projects/`, `cache/`, `history.jsonl` [fact:https://gist.github.com/rymiwe/2e5b940ae1ba981551450d318a2ee6c5]; (b) git-only shell wrapper that pulls before `claude` and pushes on exit, with an allowlist `.gitignore` [fact:https://github.com/elizabethfuentes12/claude-code-dotfiles]; (c) one canonical `~/.agent-skills` dir symlinked into each tool via chezmoi `symlink_*.tmpl` — the same pattern as this repo's `.agents/skills` → `.claude/skills`; that author also says "For agent logic, prefer documented .claude/agents/ over .claude/skills/" [fact:https://dev.to/dotwee/one-skills-brain-for-codex-claude-cursor-and-copilot-with-chezmoi-2p3k].
- What belongs where [opinion:mine]: user-level = language-agnostic habits (code-simplifier, generic test-runner, personal reviewer voice); project-level = anything that names repo paths, ADR process, or toolchain pins.

## 5. Model, `maxTurns`, tools, `permissionMode`, `memory`

- **Model tiers** are near-unanimous: haiku for file ops/search/docs, sonnet as "the workhorse", opus for "security audits, architectural critique, gnarly debugging" [opinion:tembo]; "Opus for the orchestrator. Sonnet for workers. Haiku for formatting" ≈ 40% cheaper than all-Opus [opinion:cloudzero]. Anthropic's own code-reviewer is `model: opus`; its templates default to `inherit` [fact:anthropics/claude-code]. `CLAUDE_CODE_SUBAGENT_MODEL` sets a global default [fact:https://code.claude.com/docs/en/agent-teams].
- **`maxTurns`**: caps agentic turns; output returns "marked as partial" and can be resumed [fact:https://github.com/shanraisshan/claude-code-best-practice/blob/main/best-practice/claude-subagents.md]. Given #61405, set it on every research agent [opinion:mine].
- **Tools**: reviewers `Read, Grep, Glob`; "When 'please only read' matters, back it with a hook that makes it read-only" (PreToolUse exit 2) — "enforce, don't trust" [opinion:dev.to]. `disallowedTools` also exists [fact:shanraisshan].
- **`permissionMode`**: `default | acceptEdits | auto | dontAsk | bypassPermissions | plan`; "bypassPermissions is dangerous. It skips all permission prompts, including writes to .git, .claude" [fact:tembo]; plugin-shipped agents ignore it, so copy into `.claude/agents/` [fact:tembo].
- **`memory`**: introduced v2.1.33 (Feb 2026); scopes `user` (`~/.claude/agent-memory/<name>/`), `project` (`.claude/agent-memory/<name>/`, committable), `local`; first 200 lines of `MEMORY.md` injected; Read/Write/Edit auto-enabled; must instruct "Before starting, review your memory. After completing, update your memory" [fact:https://github.com/shanraisshan/claude-code-best-practice/blob/main/reports/claude-agent-memory.md]. Memories are per-agent silos — "Your code-reviewer subagent's MEMORY.md is invisible to your security-auditor" [fact:https://hindsight.vectorize.io/blog/2026/05/06/claude-code-subagents-shared-memory]. Sources disagree on default scope (shanraisshan: `user`; hidekazu: `project`); use `project` for anything repo-specific so it rides along in git [opinion:mine].

## 6. Description and return-format patterns

- **Descriptions are router rules.** Anthropic's shape: "Use this agent when... should be used proactively after..." + 2–3 `<example>` blocks with `<commentary>`, and a line telling the caller what input to pass [fact:pr-review-toolkit]. Docs: include "use proactively" [fact:https://code.claude.com/docs/en/sub-agents]. Community: "Use immediately after writing or modifying code" beats "helps with code quality"; "Make it a router rule, not a job posting" [opinion:dev.to]; name the trigger condition, not the capability [opinion:tembo].
- **Return format** belongs in both the description and the body. Anthropic: an "output format" is mandatory in every delegation [fact:multi-agent-research-system]; target "1,000-2,000 tokens" [fact:context-engineering]; every finding as `path:line` grouped by severity, ≥80 confidence [fact:anthropics/claude-code]. Community: write long output to `review-<task>-rN.md` and "return only a concise summary... a few sentences of orientation" [opinion:rajivprab]; "Aggressively summarize in the system prompt" [opinion:tembo]. A workable stanza: "Return ≤200 words: verdict, then findings as `path:line — issue — fix`, max 10; write anything longer to `<file>` and cite it" [opinion:mine].

## 7. Interplay with skills

- Framing: "skills as knowledge repositories and subagents as delegated workers" [opinion:https://alexop.dev/posts/understanding-claude-code-full-stack/]; "Skills extend what the main agent can do. Subagents replace the main agent for one task" with a 4-step test (needs own context window? cheaper model? restricted tools? else skill) [opinion:https://theaiarchitects.com/blog/claude-code-subagents-vs-skills]. Contrarian: "Reach for subagents first. Move to skills when you want the same instructions in line" [opinion:tembo].
- `context: fork` runs a skill in a subagent: "The skill content becomes the prompt that drives the subagent... It won't have access to your conversation history"; `agent:` picks `general-purpose | Explore | Plan | Bash`; use for multi-file synthesis or exploratory searches, not for simple skills or when intermediate results are needed [fact:https://shiqimei.github.io/posts/claude-code-fork-agent-subagents].
- `skills:` in agent frontmatter injects "the full skill content, not just the description" — the cleanest way to give a worker repo knowledge without duplicating CLAUDE.md [fact:hidekazu]; agent-team teammates ignore that field [fact:https://code.claude.com/docs/en/agent-teams].
- Note for the docs-covering agent: current docs also describe a *fork-mode subagent* that inherits the parent conversation, distinct from `context: fork` skills [fact:https://code.claude.com/docs/en/sub-agents] — worth reconciling.

## 8. Anthropic 2026 guidance on Teams / Workflows / fleets

- **Agent Teams** (Feb 5, 2026, v2.1.32, research preview) [fact:https://www.cloudzero.com/blog/claude-code-agents/]: "check whether a lighter option does the job"; "significantly more tokens"; start with 3–5 teammates on research/review, not implementation; "Two teammates editing the same file leads to overwrites"; enabling teams makes any *named* subagent launch as a teammate [fact:https://code.claude.com/docs/en/agent-teams]. Solo-dev take: "Skip agent teams for personal projects with tight token budgets"; justified when "time saved > 2x token cost increase" [opinion:https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/workflows/agent-teams.md].
- **Dynamic Workflows** (May 28, 2026): Claude writes a JS script that runs "tens to hundreds of parallel subagents"; they "fill the gap between firing off a single subagent and building out a full agent team"; "can consume substantially more tokens" [fact:https://claude.com/blog/introducing-dynamic-workflows-in-claude-code]. "You own the loops and fan-out, agents do the thinking"; reach for it for breadth ("review every file in this diff"), adversarial verification, or "anything bigger than one context can hold" [opinion:https://alexop.dev/posts/claude-code-workflows-deterministic-orchestration/].
- **Agent View** (May 11, 2026): `claude --bg`, `/bg`, one screen for background sessions and "PR babysitters" [fact:https://claude.com/blog/agent-view-in-claude-code].
- **Code w/ Claude** (May 12, 2026): Managed Agents gain lead→specialist orchestration, "Dreaming" (scheduled memory curation), and "Outcomes" (a separate grader in its own context) [fact:https://claude.com/blog/code-w-claude-sf-2026-sf].
- **Best-practices doc**: `/batch` splits a change across 5–30 worktree subagents; add an "adversarial review step" via a fresh-context subagent; `/goal` and Stop hooks as gates [fact:https://code.claude.com/docs/en/best-practices].

**Bottom line for a solo dev** [opinion:mine]: five to seven narrow, read-mostly agents with trigger-shaped descriptions, `maxTurns`, and file:line return formats; skills for repo knowledge and gated workflows; background sessions/Routines for babysitting; Teams and Workflows only for breadth problems you can't fit in one context.
