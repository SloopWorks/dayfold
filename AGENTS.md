# AGENTS.md

Dayfold's canonical agent-operating doc is **[`CLAUDE.md`](CLAUDE.md)** — session
protocol, directory map, process rules, and guardrails. Read it first; this file
exists only because some agent tooling looks for `AGENTS.md` by convention
(fulfills the commitment in `adr/0013-client-architecture-kmp-redux-kotlin.md`
§6) and is kept deliberately thin to avoid a second copy of the same rules
drifting out of sync.

## Fast orientation for a cold agent

- **Governance / how to work here:** `CLAUDE.md` (start-of-session routine,
  confidence protocol, hard guardrails — read before substantive work).
- **What Dayfold is:** `README.md`.
- **How the system is wired:** `docs/architecture.md`.
- **Build/test toolchain + cheap feedback loops** (Compose/KMP client+UI,
  Android, iOS, CLI, API): `processes/agent-dev-loop.md` — scoped by area, so
  CLI-only or API-only work doesn't pay for the Compose/KMP section.
- **What's currently in flight:** `backlog/now.md`; **what's queued:**
  `backlog/next.md`; **operator decisions awaiting an answer:**
  `backlog/operator-inbox.md`.
- **Decisions already made (don't re-litigate):** `adr/decisions-index.md`.
- **Subagents (reviewers, verifiers, auditors) + when to use them:**
  `processes/subagents.md`. Definitions are **generated** from the SloopWorks
  agent pack into `.agents/roles/` (harness-neutral) and `.claude/agents/`
  (Claude Code); repo parameters live in `.agents/profile.yml` and the
  repo-specific review knowledge in `processes/repo-review-contract.md`. The
  review gate is the `two-round-review` skill.
- **The `dayfold` CLI + curator skill** (the content-authoring surface):
  `apps/cli/templates/README.md` and `.agents/skills/dayfold-curator/` — one
  harness-neutral copy; `.claude/skills/dayfold-curator` symlinks to it, so edit
  only the `.agents/` path.

If anything below conflicts with `CLAUDE.md`, `CLAUDE.md` wins.

## SloopWorks factory roles

This repo carries the SloopWorks agent pack. Role contracts live in
`.agents/roles/<role>.md`; repo parameters (module paths, verify commands,
gates) live in `.agents/profile.yml`. Read the role file before acting in that
role, and resolve every `paths.*` / `verify.*` reference through the profile.

All three harnesses dispatch these as real subagents: Claude Code from
`.claude/agents/`, Grok Build from that same directory, Codex from
`.codex/agents/*.toml` (ask for the role by name — Codex spawns a subagent
only when you ask). Anywhere that is unavailable, adopt one role at a time:
*"Act as `<role>`; follow `.agents/roles/<role>.md`"* — and run a review role in
a fresh session, not in the authoring context. A reviewer that shares the
author's context confirms the author.

| role | stage | authority | purpose |
|---|---|---|---|
| `brief-shaper` | intake | write-docs | Turns a rough request into a dispatchable work item: problem, surface, acceptance criteria, Product Atlas IDs, autonomy tier, and the gates it must clear |
| `design-director` | design | write-docs | Owns the design round: writes the self-contained Claude design prompt, receives the returned spec/mockup, and checks it against the SloopWorks design system before any code exists |
| `plan-author` | plan | write-docs | Turns a brief (+ accepted design spec) into an ordered, test-first implementation plan with explicit file-level targets, verification commands, and stage gates |
| `kmp-implementer` | build | write-code | Implements client work in Kotlin Multiplatform + Compose Multiplatform against an accepted plan, test-first, honoring the design system and redux-kotlin rules |
| `swip-instrumenter` | build | write-code | Wires analytics, telemetry, and remote config through SWIP with the right privacy class, schema registration, and debug-drawer visibility |
| `adversarial-reviewer` | verify | read-only | Round-1 correctness reviewer with a hostile mandate, never the author |
| `compose-ui-reviewer` | verify | read-only | UI reviewer for Compose Multiplatform changes |
| `kmp-verifier` | verify | read-only | Runs the repo's Kotlin/Compose verify lane exactly as CI does (common/desktop tests, Android/iOS compile, lint, stability and console gates) and reports results read from machine output, not from vibes |
| `privacy-security-reviewer` | verify | read-only | Deep security + privacy pass |
| `simplification-reviewer` | verify | read-only | Round-2 reviewer: usability at the point of use, redundancy, over-engineering relative to the next few uses, dead code |
| `ci-doctor` | verify | read-only | Diagnoses a red or suspicious CI run — failing job, root cause, exact fix, or a justified single re-run — without calling anything a flake on faith |
| `doc-drift-auditor` | steward | read-only | Audits agent-facing docs (CLAUDE.md, AGENTS.md, README, architecture docs, ADR index, runbooks, role profiles) against the code and git history and returns every stale factual claim with evidence and exact replacement text |
| `release-shepherd` | ship | write-ops | Takes verified work to a device or a store: picks the channel, runs the publish path (Shipyard Deploy dev builds, TestFlight, Play, Cloudflare deploy command), and checks the release prerequisites the company actually owes |
| `api-verifier` | verify | read-only | Runs the repo's backend/schema verify lane as CI does (unit/contract tests, codegen idempotence, schema and bundle drift, migration checks, worker dry-run) and reports machine-read results |
| `research-verifier` | intake | read-only | Cite-or-die verification of external claims against live sources |
| `viability-skeptic` | intake | read-only | Hostile reviewer of strategy, viability, pricing, and research syntheses |

Pipeline: intake → design → plan → build → verify → ship, with `steward` roles
on a maintenance cadence. Do not skip a gate the profile declares in `gates.*`.
