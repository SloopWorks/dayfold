When Dayfold adds something you don't want

Smart content is minted by three machines — the on-device derived lane (ADR 0043), the curator, and subscription routines (ADR 0061). Today the only recourse is Hide: local, one card at a time — and the next run mints the same card again. Whack-a-mole. This board explores the missing verb: a response stored in Dayfold so future processing doesn't re-create similar content.

Everything here is a candidate, not a decision. Full brainstorm, precedent survey and open questions: NOTES.md in this folder.

Where each response lives

The load-bearing distinction: a hide is passive behavior — syncing it is the who-saw-what leak ADR 0039 refused. A mute is an intentional, user-authored policy: attributed, visible in Settings, editable. That's what makes it safe to store in Dayfold — and storing it is the whole point, so the pipeline stops re-creating the content.

key
subjectRef does the work. ADR 0043 gave every Now item a subject key for dedup and deep-linking. A mute rule is keyed by the same ref (or a kind/source label) — so changeset validation can reject "re-create a muted subject" mechanically, by ID, with the server staying content-blind, and the routine gateway filters candidates pre-run from the decrypted list. Done states ride the same key: next run, the same source email extracts to a subject already marked complete — resolved, not re-mintable. Extraction must therefore produce a stable subject key from the same source across runs.

Me vs the family — the copy decision

Routine cards are family-visible, so every mute needs a scope answer, spoken plainly on the sheet.

DEFAULTRECOMMEND
Personal mute
The routine keeps minting for others and excludes you from the card's audience. Nobody else's feed changes; nobody is notified.
"Won't be added for you — your family's feed is unchanged."
EXPLICIT SECOND CHOICETEST
Family-wide mute
For family-scoped noise (weather, generic reminders). Always attributed — "Muted by Mom" — visible to all in Settings, reversible by any adult. Never on the swipe path.
"Won't be added for anyone — your family can see and undo this in Settings."
